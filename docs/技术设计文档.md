# 考证刷题平台技术设计文档

版本：1.1｜日期：2026-10-31（初版 2026-10-23）｜状态：技术设计基线

需求来源：[需求规约](./需求规约.md)

Spec Kit 实施计划：[plan.md](../specs/001-cert-practice-platform/plan.md)

## 1. 设计目标

本设计将需求规约转换为可实施的前后端分离方案，核心技术目标如下：

- 用户端和管理端共用 Vue 3 + TypeScript 前端工程，通过 `/app`、`/admin` 分区。
- Java Spring Boot 作为唯一业务后端，独占 PostgreSQL 业务数据写入。
- Python FastAPI 作为无状态 AI 服务，只负责模型编排、生成和回答，不直接访问业务数据库。
- 题目版本、练习会话和题解讨论可追溯，历史成绩不受后续题目修改影响。
- 练习提交前不返回答案、官方解析或可泄题的题目专属 AI 能力。
- 在 2～3 人团队和本地开发约束下，使用模块化单体和 PostgreSQL 完成任务、额度及审计状态管理。

首期不引入微服务、Redis、消息队列、Elasticsearch、Nginx 或 Kubernetes。正式部署、生产备份和监控不属于当前交付范围。

## 2. 总体架构

```text
Browser
├─ /app     用户端
└─ /admin   管理端
        │ HTTPS/JSON + HttpOnly Cookie + CSRF
        ▼
Vue 3 SPA
        │ REST /api/v1
        ▼
Java 21 / Spring Boot 3
├─ identity, catalog, question, practice
├─ selftest, community, notification, admin
├─ ai-gateway
├─ Spring Session
└─ PostgreSQL 16
        │ internal REST + service token
        ▼
Python 3.12 / FastAPI
└─ prompt, model adapter, Mock provider
        │ HTTPS
        ▼
Single external model provider
```

### 2.1 运行边界

| 边界 | 所有权 |
|---|---|
| 用户、题目、练习、社区、通知、额度、审计 | Java 后端 |
| 身份会话与权限 | Java + Spring Security |
| 业务事实数据 | PostgreSQL |
| 模型提示词、供应商协议、流式输出适配 | Python AI 服务 |
| 页面状态与交互 | Vue SPA |

Python 不持有持久业务状态。AI 对话、额度、任务和候选变式题的持久化均由 Java 完成。

### 2.2 通信协议

- 浏览器与 Java：`/api/v1` JSON REST，HTTP 200/201/204 及 RFC Problem Details 错误响应。
- Java 与 Python：`/internal/v1` JSON REST，共享服务令牌；请求包含 trace ID、超时和模型配置标识。
- Java 与 PostgreSQL：JPA 负责读写，Flyway 负责迁移。
- Python 与模型供应商：通过统一 `ModelProvider` 适配器，不向业务代码暴露供应商 SDK。

## 4. 前端设计

### 4.1 技术组成

- Vue 3 + TypeScript + Vite。
- Vue Router 负责 `/app` 和 `/admin` 路由分区。
- Pinia 管理当前用户、权限摘要和少量 UI 偏好；全局未读通知角标暂未实现，后续作为体验增强。
- Element Plus 作为统一组件库，桌面布局优先。
- 服务端数据由 `features/*/api.ts` 和组合式函数管理，不复制到全局 Store。
- 现有媒体查询为 480 px、768 px、960 px：360 px 落在 480 px 断点内，1280 px 使用桌面默认布局；T153 按 360/768/1280 视口验收，首期保证移动端核心页面可操作。

### 4.2 路由与权限

| 路由区 | 页面 | 权限 |
|---|---|---|
| `/app` | 首页、题库、练习、填空详情、自测、记录、收藏、错题、讨论、通知、AI、个人中心 | 登录用户 |
| `/admin` | 题目、审核、导入、目录标签、举报报错、用户、看板、AI 任务与额度、审计 | 管理员 |

路由守卫只负责交互体验。所有权限、资源归属和角色限制必须由 Java 后端再次验证。

### 4.3 状态与错误处理

- API 客户端统一附加 CSRF 头和 trace ID；创建会话、提交和自评按需附加 `Idempotency-Key`。
- 401 清理本地会话并跳转登录；403 显示无权限；409 显示状态冲突或重复提交。
- 提交按钮在请求中只锁定当前操作，不锁定整页。
- 练习页面依赖服务端返回的 `allowedActions`，不自行推断答案可见性和 AI 可用性。

## 5. Java 后端设计

### 5.1 模块职责

| 模块 | 职责 |
|---|---|
| identity | 注册、登录、退出、用户状态与角色 |
| catalog | 证书、科目、章节、标签树与筛选 |
| question | 题目实体、版本、审核、发布、下线、搜索、导入、纠错报告实体 |
| practice | 练习会话、抽题、作答、判题、自评、记录、收藏、错题 |
| selftest | 自测范围、组题策略、原题与 AI 变式比例 |
| community | 讨论帖、一级评论、内容举报、纠错提交与处理编排、屏蔽与下架 |
| notification | 站内通知生成、查询和已读状态 |
| admin | 用户管理、看板、审计查询和跨模块管理编排 |
| aigateway | AI 会话、防泄题门禁、额度、模型适配调用和生成任务 |

### 5.2 分层规则

- Controller 只处理协议校验、身份上下文和响应映射。
- Application Service 定义事务边界和跨实体流程。
- Domain Service 处理抽题、判题、状态转换等纯业务规则。
- Repository 默认只在本模块内使用；跨模块协作应调用公开应用接口或查询端口。既有 P1/P2 模块的跨模块 Repository 引用作为遗留例外保留，新模块不得继续扩大。
- Entity 不直接作为 API 响应。DTO 按访问状态裁剪字段。
- Flyway 是数据库结构唯一变更入口。

### 5.3 事务边界

以下操作必须使用单事务：

- 创建练习会话：校验范围、选够题目、保存会话与固定题目版本。
- 提交练习：锁定会话、保存答案、计算单选结果、转换状态、处理错题。
- 完成填空自评：保存自评、判断是否全部确认、生成最终结果。
- 发布新版本：锁定题目身份、创建或确认版本、切换 `published_version_id`、写审计。
- 消费 AI 额度：锁定个人与团队账本、写入预占、记录请求标识。
- 确认批量导入：校验任务版本、写入题目与失败信息、写审计。

外部 AI 调用不得置于数据库事务内。Java 先提交额度预占和请求状态，再调用 Python，最后以独立事务结算。

## 6. Python AI 服务设计

### 6.1 接口

- `POST /internal/v1/chat`：接收已裁剪上下文和对话消息，返回完整答案或流式片段。
- `POST /internal/v1/generate-variants`：接收原题、知识点和生成约束，返回候选变式题。
- `GET /health/live`、`GET /health/ready`：进程和供应商配置健康状态。

### 6.2 约束

- 不访问 PostgreSQL，不保存会话、额度或业务日志。
- 请求和响应使用 Pydantic 模型验证。
- 超时、重试和供应商错误转换为稳定内部错误码。
- 模型名称、地址和密钥来自环境变量；支持 MockProvider。
- 提示词版本独立记录。日志不得写入密钥、完整用户输入或官方答案。
- 首期只接一个真实供应商，不自动切换模型。

## 7. 数据与版本策略

### 7.1 题目版本

- `question` 是稳定题目身份，保存科目、类型和当前发布版本指针。
- `question_version` 保存题干、解析、难度、来源、作者、审核人和版本号。
- 选项、填空规范答案、可接受别名、标签关联均按版本保存。
- 已发布版本不原地修改。编辑时从当前版本复制出新草稿，发布后切换指针。
- 旧版本仍保留 `PUBLISHED + superseded_at` 语义，以支持历史记录；新练习只使用 `published_version_id`。
- 已发布题目下线时清除可抽取状态但不删除数据；草稿可按管理规则删除。

### 7.2 练习快照

创建会话时固定：

- 题目身份和题目版本 ID。
- 题目顺序。
- 范围、标签、难度、历史时间窗口等筛选快照。
- 抽题规则及版权重。
- 题目来源：`ORIGINAL` 或 `AI_VARIANT`。

后续题目修改、标签调整或下线均不影响该会话展示和历史结果。

### 7.3 会话状态

```text
IN_PROGRESS
├─ 纯单选 → COMPLETED（答案冻结、判题完成）
└─ 含填空 → PENDING_SELF_ASSESSMENT → COMPLETED（全部自评后）

任意未提交状态可 → ABANDONED
```

提交后的答案冻结与判题在同一事务内完成：纯单选会话直接进入 `COMPLETED`，含填空题的会话进入 `PENDING_SELF_ASSESSMENT`。`SUBMITTED` 仅作为兼容枚举值保留，当前实现不在状态机中写入；后续新增功能应按 `COMPLETED` 判断本题 AI 是否可用。

### 7.4 答案可见性

| 会话状态 | 题干/选项 | 规范答案 | 官方解析 | 本题讨论 | 本题专属 AI |
|---|---:|---:|---:|---:|---:|
| 未创建/普通浏览 | 是 | 否 | 否 | 默认隐藏 | 否 |
| `IN_PROGRESS` | 是 | 否 | 否 | 隐藏 | 否 |
| `PENDING_SELF_ASSESSMENT`（含填空） | 是 | 是 | 是 | 是 | 否 |
| `COMPLETED` | 是 | 是 | 是 | 是 | 是 |

首页通用 AI 不自动携带当前题目，但无法阻止用户手动粘贴题目；系统不承诺考试级防作弊。

完整表、约束和索引见 [data-model.md](../specs/001-cert-practice-platform/data-model.md)。

## 8. 核心流程

### 8.1 注册、登录与注销

1. 注册接口只接受普通用户字段，忽略或拒绝客户端提交的角色。
2. 用户名经 NFKC、去首尾空白和 ASCII 小写归一化后唯一。
3. 密码使用 BCrypt（cost 12）哈希，失败时返回统一错误。需求规约允许 BCrypt 或 Argon2；2026-10-31 决策保持 BCrypt，不迁移 Argon2id。
4. 登录成功创建服务端会话和 HttpOnly Cookie。
5. 每次受保护请求重新读取用户状态，禁用用户立即失去访问权。
6. 只有普通用户可自行注销；管理员调用注销接口返回 `403 ADMIN_CANNOT_DELETE_SELF`。

### 8.2 题目创建、审核与发布

1. 管理员创建题目身份和草稿版本。
2. 草稿可编辑，提交后进入 `PENDING_REVIEW`。
3. 审核通过后在同一事务中标记版本可发布并切换题目当前发布指针。
4. 修改已发布题目会创建新草稿；发布后旧版本保留并标记为已被替代。
5. 下线只影响新会话抽题，不删除历史练习和讨论。

### 8.3 普通练习

1. 服务端解析目录、标签、难度和题型条件。
2. 查询满足条件的当前发布版本，按未见、错题、普通已做分桶。
3. 应用难度目标和桶权重，抽取会话内不重复的 10 题；不足时从合法题回退。
4. 保存会话、题目版本和规则快照，返回不含答案的安全 DTO。
5. 用户可反复更新未提交答案；提交时锁定会话并一次计算全部单选结果。
6. 返回冻结答案、逐题结果与解析；重复提交按幂等结果返回，不生成第二份成绩。

默认权重为未见 50%、错题 30%、普通已做 20%。默认目标难度比例建议为易 30%、中 50%、难 20%，全部作为配置项。

### 8.4 填空与自评

1. 用户提交单空答案前，接口不返回规范答案或解析。
2. 提交时对输入执行 NFKC、去首尾空白、连续空白折叠和 ASCII 小写化。
3. 与规范答案及别名比较，得到 `MATCH`、`MISMATCH`，不进行数值容差或单位换算。
4. 展示参考答案、解析和自动匹配建议，会话进入待自评。
5. 用户逐题选择成功或失败；每个会话题目只能有一条最终自评。
6. 全部自评后在同一事务产生最终结果，统计分别记录自动匹配率和自评通过率。

### 8.5 个性化自测

1. 用户提交目录、标签、历史窗口和题量。
2. 查询已审核原题与已发布 AI 变式题。
3. 默认按 60% 原题、40% 变式题作为目标；原题内部使用未见、错题、普通题权重。
4. 变式题不足时用原题补齐；合法题不足 10 道时使用现有数量；零题拒绝创建。
5. 保存实际来源组成，并在结果页明确展示。

历史窗口默认 90 天，薄弱知识点默认按自评失败权重排序。两项均写入规则快照。

### 8.6 AI 辅导

1. 首页通用会话不自动附加题目上下文。
2. 题目完成前，AI 创建接口校验会话状态并返回 409。
3. 完成后 Java 构造最小上下文：题干、题型、用户答案、自评结果和允许的解析字段。
4. 官方答案是否进入模型上下文由 `ai.send-official-answer` 配置控制，默认关闭。
5. 每次请求先原子预占个人日额度与团队预算，再调用 Python。
6. 成功或供应商已计费时记成本；可退款失败退还个人次数，但保留实际成本记录。
7. 用户从自己的 AI 记录中清空会话，不删除团队成本审计。

### 8.7 AI 变式题

1. 管理员按章节或知识点创建生成任务，目标数量默认 30～50。
2. Java 将任务置为待执行，调度器使用数据库状态领取任务，无消息队列。
3. Python 返回结构化候选题，Java 校验格式、答案、选项和重复性。
4. 候选内容进入待审核区，绑定原题版本、任务、模型和提示词版本。
5. 管理员逐题或批量审核；发布后进入变式题池，只有已发布版本能被自测抽取。

### 8.8 讨论、举报与通知

- 帖子绑定题目版本；新版本发布后旧帖保留并显示版本提示。
- 评论只允许一层父子关系，引用回复不作为新层级。
- 发布后可见，执行敏感词和链接过滤；用户可举报，管理员可隐藏或下架。
- 评论回复、内容处理结果和系统公告通过事务内通知记录生成。
- 通知只有已读/未读状态，不接短信、邮件或即时通信。

## 9. API 契约

基础路径为 `/api/v1`，管理端统一位于 `/api/v1/admin`。详细资源、字段裁剪、状态码和错误码见 [HTTP API 契约](../specs/001-cert-practice-platform/contracts/http-api.md)。

通用规则：

- 成功响应直接返回资源或 `{ "items", "page", "size", "total" }`。
- 错误使用 `application/problem+json`，包含 `type`、`title`、`status`、`detail`、`code`、`traceId`。
- 日期使用 ISO 8601 UTC，前端按本地时区展示。
- ID 使用 UUID；数据库内部允许独立的单调序号用于排序。
- 创建会话、提交、自评完成和 AI 消息接受 `Idempotency-Key`。
- 分页最大 100 条。
- 所有响应由 DTO 白名单构造，禁止直接序列化实体。

实现阶段必须维护 OpenAPI 3.1 文件并进行契约测试。本文件中的 Markdown 契约是当前设计基线。

## 10. 安全设计

- Spring Security 服务端会话，Spring Session JDBC 持久化到 PostgreSQL。
- Cookie：`HttpOnly`、`SameSite=Lax`，正式环境启用 `Secure`；不使用 localStorage JWT。
- 状态变更请求校验 CSRF token。
- 用户名唯一、密码哈希、登录失败限流和临时锁定可配置。
- 管理员接口执行角色校验；用户资源同时校验所有权。
- 公开搜索和练习 DTO 不包含答案、别名、解析或正确选项标识。
- 当前通知/讨论内容按纯文本处理；若后续引入富文本，必须启用白名单净化。页面设置 CSP、X-Frame-Options 和 nosniff。
- 上传仅允许 CSV/XLSX 和受限文件大小，解析时不执行宏或公式。
- 密钥只从环境变量读取，不写数据库、不提交仓库。
- 管理操作记录操作者、动作、目标、结果、时间、trace ID 和必要变更摘要。
- 日志不记录密码、Cookie、密钥、完整 AI 提示词或未公开答案。

## 11. 一致性与并发

- 练习会话使用整数 `row_version` 进行乐观锁。
- 提交与自评使用行锁和状态前置条件，重复请求返回相同结果。
- 题目发布锁定题目身份行，避免两个管理员同时切换当前版本。
- AI 额度使用数据库行锁或单条原子更新，禁止仅依赖前端或内存计数。
- 生成任务使用 `SELECT ... FOR UPDATE SKIP LOCKED` 领取，进程崩溃后超时可重新领取。
- 删除错题、收藏和通知读取使用幂等语义。
- 事务内不执行外部 HTTP；AI 调用采用预占、调用、结算三阶段。

## 12. 搜索与性能

- 用户搜索只查询题干、章节名和标签名，不查询选项、答案和解析。
- PostgreSQL 启用 `pg_trgm`，对题干和标签名建立 GIN 索引。
- 目录和标签使用规范化关联表，多标签取交集。
- 抽题先按筛选条件加载候选（默认上限 20,000），再在应用层执行可注入随机源的加权抽样；“先计数再抽样”的进一步优化并入索引与查询调优任务。
- 默认查询候选上限 20,000 条；每次只选择 10 题，不返回完整候选题对象。
- 练习记录、通知和讨论按用户/题目 + 时间建立复合索引。
- 普通读取 p95 建议值 300 ms，普通写入与提交 p95 建议值 800 ms；这些是工程观察基线，不是产品确认后的验收门槛。外部 AI 不纳入该目标。

## 13. 错误与可观测性

- `400` 参数错误，`401` 未登录，`403` 权限不足，`404` 不存在，`409` 状态冲突，`422` 业务校验失败，`429` 额度或频率超限，`503` AI 暂不可用。
- 错误不暴露 SQL、堆栈、内部 URL 或提示词。
- 每个请求生成 trace ID，Java、Python 和审计记录共用。
- 本地输出结构化日志和健康检查；生产级指标、告警与备份在正式部署前另行设计。
- 管理看板从业务表只读聚合，首期可使用定时汇总或按请求聚合，避免引入独立分析存储。

## 15. 本地部署

本地环境由 PostgreSQL 容器、Java 应用、Python 应用和 Vite 前端组成。Java、Python 与前端可分别启动，数据库通过 Docker Compose 管理；也可将其余服务纳入 Compose。

```text
frontend   http://localhost:5173

Python AI  http://localhost:8000
```

## 17. 技术默认值与待确认项

以下设计允许实现继续推进，但上线前应由产品确认：

| 项目 | 技术默认值 | 配置化 |
|---|---|---|
| 首发证书/科目 | 由数据库种子数据指定，不硬编码 | 是 |
| 难度目标 | 易 30%、中 50%、难 20% | 是 |
| 自测历史窗口 | 90 天 | 是 |
| 填空规范化 | NFKC、空白折叠、ASCII 小写；无数值容差 | 规则版本化 |
| AI 供应商与模型 | 未指定；本地默认 Mock，已确认存在真实额度 | 是 |
| AI 官方答案上下文 | 默认不发送 | 是 |
| 导入失败处理 | 首期固定整批不落库，后续再考虑配置化 | 否（首期固定） |
| 注销数据保留期 | 技术预留 `deleted_at`，保留期待产品确定 | 是 |

这些默认值不改变已确认需求；实现不得把未确认参数写死在业务代码中。
